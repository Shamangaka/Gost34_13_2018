# SECURITY — Qalqan Research-Only

## Запрет на использование как готового СКЗИ

**Исследовательский код. Не используйте для защиты реальных конфиденциальных
данных и в государственных/промышленных системах без отдельной верификации,
защитного протокола и необходимых процедур оценки соответствия.**

## Известные ограничения по языкам

- **Rust v8:** S-box заменён экспериментальной функцией без прямого
  секретного индекса таблицы, проверенной для определённых x86-64 сборок.
  Формальная проверка constant-time, taint-анализ, аудит LTO-бинарника и
  проверка на целевом железе отсутствуют. `zeroize` очищает часть буферов
  по принципу best-effort; остаточные копии возможны.
- **C++ v20:** публичный API `QalqanCipher`/режимов использует
  `std::span` с проверками размеров/перекрытия. Низкоуровневые функции
  с сырыми указателями сохранены во внутреннем заголовке и **не считаются
  безопасными для некорректных размеров буферов**. S-box и `Kexp` используют
  секретно-зависимые табличные обращения; **не constant-time**.
- **Go v21:** S-box и `Kexp` табличные; **не constant-time**.
  `Reset()` обнуляет сохранённый ключ и блокирует дальнейшее использование,
  однако Go runtime может оставить копии в памяти.

## Режимы

- ECB раскрывает повторяющиеся блоки.
- CBC/CFB/OFB/CTR **не аутентифицируют** шифртекст. Манипуляции атакующего
  могут менять расшифрованные данные, а различимый результат проверки
  дополнения CBC создаёт риск padding oracle.
- Нельзя применять CBC + проверку padding к недоверенным шифртекстам
  без предварительной корректной аутентификации.
- CTR/OFB требуют уникальных для данного ключа диапазонов потока. Повтор IV
  при том же ключе или пересечение диапазонов CTR приводит к повтору потока.
- `ctr_no_wrap` в Rust v13 запрещает переполнение **в пределах одного вызова**,
  но не предотвращает повтор IV и пересечение диапазонов **между вызовами**.
- Rust/C++ обрабатывают одно сообщение на вызов и заново стартуют от IV;
  Go cipher.Stream хранит состояние между вызовами. Не переносите код
  обработки чанками между ними без явной адаптации.
- CTR счётчик кодируется big-endian, на всю длину блока, со сбросом при
  переполнении в legacy API. Это соглашение реализации, а не однозначная
  нормативная интероперабельность. `ctr_no_wrap` — opt-in.
- Для CBC необходим корректный уникальный/непредсказуемый IV согласно
  выбранной системе безопасности. Все требования к IV и лимитам объёма
  данных — ответственность интегратора; библиотека их не обеспечивает.

## Режимы отказа и ошибки

Несмотря на все тесты, возвраты ошибок/panic/exception для неправильных
параметров не унифицированы между языками. Не раскрывайте наружу подробности
проверки дополнения. Низкоуровневые внутренние функции вне публичного API
могут требовать соблюдения предусловий о длине памяти.

## Проверки и ограничения доказательств

Тесты, ASan/UBSan и SAST подтверждают только исследованные пути.
Тест v22 не доказывает криптографическую стойкость, constant-time,
устойчивость к активным атакам или сертификацию. Для этих свойств нужны
самостоятельные работы, не входящие в этот релиз.
